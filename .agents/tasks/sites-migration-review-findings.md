# Codex review findings for Kiro follow-up

Fix these before production publication. Do not deploy or operate Sites tools.

1. `Repository.publishFeed` is unconditional after a lease claim. A slow holder A can run past its lease expiry, holder B can acquire the lease and publish newer data, then A can overwrite B. Carry the actual lease holder from `refreshFeed` through `executeRefresh` into `PublishPayload`, and validate ownership inside the same D1 batch before any deletion or insertion. A transaction-fatal first statement can use the existing `app_state.value NOT NULL` constraint: insert/update a fixed operational key whose value comes from a scalar SELECT of the matching, still-held `refresh_lease` row. A missing holder produces NULL and rolls the entire batch back. Do not rely on a separate pre-batch ownership check or a no-op UPDATE followed by unconditional writes. Include a regression test that A loses its lease to B, B publishes, and A's publication fails with B's feed intact. Keep injected test clocks coherent. Token fencing inside the transaction is essential; an expired token can finish only if it was never superseded and not released.

2. `Repository.readFeed` first reads feed metadata, then independently reads events/components/provenance/etc with Promise.all. A refresh may commit between those reads, mixing old metadata, new cards and score breakdowns. Read the published metadata and all child tables needed for a view in one D1 read batch transaction. The returned view must represent one publication. Prefer simple row types and casts over speculative generic machinery. `readPublishedEvents` also needs metadata/existence and events to come from one read batch, since it is used for changes. Retained history can be read separately as an append-only advisory list if the feed cards and scoring/provenance remain consistent. Test with a database hook that a simulated concurrent publication cannot produce mixed metadata and rows.

3. Codex has patched `time.ts` to reject impossible dates and out-of-range clocks before `Date.parse` (which accepts February 30 and 24:00). Preserve that patch and add a regression case for a malformed live row whose timestamp otherwise normalizes onto the target date. This must fail the whole refresh while retaining the prior feed.

4. Do not commit `tsconfig.tsbuildinfo`; add the ignore rule and remove that generated artifact. Ensure example env files are explicitly allowed by .gitignore if intended to be committed. Node's strip-only runner rejects TypeScript parameter properties in walking.ts/d1.ts/repository.ts. Resolve this through erasable constructor fields or a documented Node transform-types flag in tests.

5. `bearerToken` must read only the application's `Authorization` header. `OAI-Sites-Authorization` is a distinct platform service-access credential, checked/consumed by dispatch; it must never be compared against VFR_REFRESH_TOKEN. Preserve owner-private service access if dispatch forwards that header on any path.

6. Replace the visitor-facing schema failure message `Apply the database migration` in feed.ts with a plain temporary-unavailable message. Keep schema diagnostics server-side and in README, because a visitor cannot fix deployment internals.

7. `buildEventShell` uses dedupKey as physical event.id, although clusterBlock correctly keeps distinct AnchorLink native IDs separate. Two different native events with identical date/title/location/rounded time therefore collide in pipeline.byId and the events primary key. For a single provider-native identity, derive the physical ID from target date and source identity. Retain dedupKey as its separate fingerprint. Test that two distinct numeric AnchorLink IDs with otherwise identical fields both publish and retain separate source/provenance/components and calendar downloads.

8. The relaxed events_feed_identity index does not support duplicate identities: event_changes still has a (feed_date, identity_key) primary key, and previousByIdentity collapses duplicates. Restore the unique feed identity invariant after fixing provider-native physical IDs; keep applied migration history immutable and generate a new schema delta when needed. Do not present ambiguous identities as merely cosmetic.

9. Regular food/verification/change labels should use 14px (prefer rem equivalents). For grid tracks, cap minimum track sizes by the container: minmax(min(100%, 15rem), 1fr) and the equivalent 13rem status grid. This prevents horizontal clipping at narrow widths and enlarged text. Remove `This is a genuine empty result, not a loading state` from the product page; the existing empty-result sentence sufficiently describes what the source returned. Avoid exposing internal binding/config exception details in the browser page's catch message.
